阅读进度条看起来是个小功能，但实现方式差别很大。这里记录三种，从最省事的到最准确的。

## 一、滚动容器的 `scroll()` 时间线

```css
.progress {
  animation-timeline: scroll(root block);
  animation-name: grow;
}

@keyframes grow {
  from {
    scale: 0 1;
  }
  to {
    scale: 1 1;
  }
}
```

零 JavaScript，但只有较新的浏览器支持。作为渐进增强非常合适。

### 降级处理

不支持 `animation-timeline` 的浏览器只会看到一个静止不动的空进度条，所以要么用 `@supports` 隐藏它，要么保留一个 JS 版本兜底：

```css
@supports (animation-timeline: scroll()) {
  .progress {
    display: block;
  }
}
```

## 二、`IntersectionObserver` 哨兵

在正文里的每个标题处放一个哨兵元素，观察哪个最后经过视口顶部。这种方式能给出「读到第几节」，比纯百分比更有意义。

### 为什么阈值要选 35%

阈值决定了「当前小节」的判定点。取视口高度的 35% 意味着标题越过这条线就算读到了，比贴着顶部更贴近人眼的实际读数位置。

## 三、基于内容的百分比

最准确的做法是拿「视口底部」和「正文实际高度」比较：

$$
\text{progress} = \frac{\text{scrollY} - \text{articleTop}}{\text{articleHeight} - \text{viewportHeight}}
$$

注意减掉视口高度，否则读到末尾时永远到不了 100%。
